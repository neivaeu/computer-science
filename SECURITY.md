--------------------------------------------------------------------------------
                      REPORTING SECURITY VULNERABILITIES
--------------------------------------------------------------------------------

  IN SCOPE

    - A script or tool contains a real exploitable vulnerability that could
      cause unintended harm if executed
    - A file accidentally exposes credentials, API keys, tokens, or
      personal data
    - A submodule URL points to a compromised or malicious source
    - An implementation demonstrates a dangerous technique without adequate
      warning, potentially misleading a user into harmful use

  OUT OF SCOPE

    - Vulnerabilities in code that is intentionally vulnerable by design
      (content in 04-laboratory/02-vulnerability-and-stress/,
      06-challenges/02-ctf-and-wargames/, and 07-chaos/)
    - Missing security best practices in historical or educational code
    - Vulnerability reports targeting third-party tools or platforms
      referenced within the repository

  HOW TO REPORT

  Do NOT open a public GitHub Issue for security vulnerabilities.

  Contact the owner privately:

    1. GitHub Security Advisory (preferred):
       Navigate to the repository → Security tab → Report a vulnerability

    2. LinkedIn (for sensitive disclosures):
       https://linkedin.com/in/neivaeu

  Your report must include:

    1. The exact file path(s) affected
    2. A clear, precise description of the vulnerability
    3. Steps to reproduce or demonstrate the issue
    4. Your assessment of severity (Critical / High / Medium / Low)
    5. Your suggested remediation (optional but appreciated)

  RESPONSE COMMITMENT

    - Acknowledgement of receipt: as soon as reasonably possible
    - Assessment and confirmation: within a reasonable timeframe
    - Remediation of confirmed in-scope issues: promptly
    - Optional credit to the reporter at the owner's discretion
